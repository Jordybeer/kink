## Brief

> Avoid generic AI-looking dashboards, purple gradients, templated cards.
> Make it feel intimate, precise, calm, data-aware — a premium relational
> analysis tool, not a corporate admin dashboard. Strong but fitting
> design direction.

The product:

- Profile-based comparison tool for kink/BDSM negotiation
- Multiple imported identities, locked fields from QR snapshots
- Longitudinal preference data (contracts over time)
- Dutch-first, mobile-first, localStorage-only, no backend

### Item 2 — Match calculation improvement *(pure logic, no UI)*

Add graded scoring to `lib/matching.ts`. Keep existing boolean exports
(`isKinkMatch`, `isHardLimit`, `isConflict`, `hasRating`) — do not remove or
change their signatures. Add new exports alongside.

**New scoring rubric:**

| A | B | Score | Kind |
|---|---|-------|------|
| yes + yes (non-directional) | | 95 | perfect |
| yes give / yes receive (complementary) | | 100 | perfect |
| yes + willing | | 75 | strong |
| yes give / willing receive (comp.) | | 85 | strong |
| willing + willing | | 60 | soft |
| maybe + yes or willing | | 45 | discuss |
| maybe + maybe | | 30 | discuss |
| any + no | | 10 | discuss |
| both want to give, neither receives | | 25 | conflict |
| any + hard_no | | 0 | limit |
| unrated | | 0 | none |

**Add to `lib/matching.ts`:**
```ts
export type MatchKind = "perfect" | "strong" | "soft" | "discuss" | "conflict" | "limit" | "none";
export interface KinkMatch { score: number; kind: MatchKind; }
export function kinkMatchScore(a: KinkEntry, b: KinkEntry): KinkMatch { ... }
export function profileMatchScore(
  a: Profile, b: Profile
): { overall: number; counts: Record<MatchKind, number> } { ... }
```

Re-implement `isKinkMatch` as `kinkMatchScore(a, b).score >= 55` so the
boolean callers keep working (willing+maybe no longer leaks into green strengths list).

Update `/compare` `ScoreMasthead` to use `profileMatchScore(a,b).overall` as the
headline percentage. Verify the confetti threshold still fires correctly after this change
(it was unified in commit `b6d5d10` to use the masthead denominator — reuse that logic
inside `profileMatchScore`).

**Files:** `lib/matching.ts`, `app/compare/page.tsx` (ScoreMasthead + score calc)

**Test required:** `__tests__/matchingScore.test.ts` covering:
perfect/strong/soft/discuss/conflict/limit/none/directional.

#### 4c — PDF rewrite

**Current problems:**
- Dark background in the PDF (wasteful to print).
- Safeword omitted (safety-critical, must be included).
- Tags and aftercare omitted.
- Magic-number page-break check (`y > 185`).
- No participant names.
- No date+time header.

**New approach:** extract all jsPDF code to `lib/scenePdf.ts`:
```ts
export async function exportScenePdf(
  scene: SceneRecord,
  opts?: { profileA?: Profile; profileB?: Profile }
): Promise<void>
```

**Document structure** (light-background, A5 portrait):
1. **Header block** (top 40mm): scene title (24pt bold `#3f1f7a`), participants
   `A — B` (12pt), date + time (10pt muted).
2. **Safeword strip** (32px, red `#fee2e2`/`#991b1b`): `SAFEWORD: [word]`.
   Omit entirely if no safeword — do not show "geen safeword".
3. **Activities table**: intensity color square + label, item name (bold), duration.
   Below each item: tags (small grey italic), then note wrapped (8pt muted italic).
4. **Summary footer**: `3× zacht · 2× midden · 1× intens · totaal 6 items`.
   Timestamp: `Geëxporteerd op dd-mm-yyyy HH:mm`.
5. **Aftercare page** (if `scene.aftercare` exists): new page, traffic-light verdict
   in text (`Geweldig` / `Goed, maar…` / `Zwaar` in appropriate color, no emoji),
   then `Wat werkte goed` / `Onthouden` blocks.
6. Page breaks: track `y` against `usableHeight = paperHeight − 20` (not magic 185).
7. File name: `kink-scene-{slug}-{yyyy-mm-dd}.pdf`.

Replace `handleExport` call site in `app/scene/page.tsx` with
`await exportScenePdf(buildSceneDraft(), { profileA, profileB })`.
Add an `Export PDF` button in `app/scenes/[id]/page.tsx` for saved/completed scenes.
