> analysis tool, not a corporate admin dashboard. Strong but fitting
> design direction.

- Profile-based comparison tool for kink/BDSM negotiation
- Multiple imported identities, locked fields from QR snapshots
- Longitudinal preference data (contracts over time)
- Dutch-first, mobile-first, localStorage-only, no backend

### Item 2 — Match calculation improvement *(pure logic, no UI)*

Add graded scoring to `lib/matching.ts`. Keep existing boolean exports
(`isKinkMatch`, `isHardLimit`, `isConflict`, `hasRating`) — do not remove or
change their signatures. Add new exports alongside, then rewrite `isKinkMatch`
body to delegate (signature stays identical).

**Design rationale:** The current boolean `isKinkMatch` flattens "I'd love to"
and "I'd tolerate it" into one green pill — exactly the corporate-flat affect
this design escapes. A graded score lets the masthead percentage and AlignmentBar
carry honest weight. `willing+maybe` no longer leaks into green strengths (intentional;
flag this in the commit message).

**New scoring rubric:**

| A | B | Score | Kind |
|---|---|-------|------|
| yes + yes (non-directional) | | 95 | perfect |
| yes give / yes receive (complementary) | | 100 | perfect |
| yes + willing | | 75 | strong |
| yes give / willing receive (comp.) | | 85 | strong |
| willing + willing | | 60 | soft |
| maybe + yes or willing | | 45 | discuss |
| maybe + maybe | | 30 | discuss |
| any + no | | 10 | discuss |
| both want to give, neither receives | | 25 | conflict |
| any + hard_no | | 0 | limit |
| unrated | | 0 | none |

## v4 Design rules (frontend-design pass)

Apply these to every new surface touched in Items 2–5.

1. **Em-dash is the v4 punctuation mark.** `{A} — {B}` pairs two named entities: `Lily — Dominant` (Item 1), `{profileA} — {profileB}` sub-meta (Item 4d), PDF participants line (Item 4c). Always the em-dash (—), always with surrounding spaces.

2. **Absence is intentional design.** No safeword → no ribbon (not "geen safeword"). No ratings → no DNA caption (not "0%"). No vibe → no pill. No custom kinks → no clause in metadata line. The visual absence communicates; do not fill it with fallback copy.

3. **Editorial register over dashboard register.** "Setlist" not "Activiteiten". "Verdeling" not "Toon meer". Cormorant italic titles on document pages. Dutch copy should read like a curator's annotation, not a form label.

4. **`rounded-xl` is banned on interior containers.** Drop to `rounded` or `rounded-sm` on any container touched for structural work.
