## Priorities

1. **P2 — Give the header utility a recognizable purpose.** The ellipsis already has a 44px touch target and an accessible label. The gap is visual recognition: users cannot tell that Settings and privacy information live there. Prefer an identifiable Settings entry with quiet, explicitly named privacy/help access. Preserve the identity above it. Impeccable: `clarify`.
2. **P2 — Reduce competing containers on empty Home.** An outer feature surface contains the outlined create action, outlined scan action and a separate rounded backup utility. Keep one clear primary action, make Scan a generous borderless row and backup a quiet text utility. Preserve readable text and 44px targets. Impeccable: `distill`.
3. **P2 — Complete import feedback and recovery.** Expose the existing `importReading` state on the ordinary restore control. The invalid/damaged profile-code error needs a next step, such as retrying or requesting a new code, instead of only Close. Impeccable: `harden` and `clarify`.

No P0 or P1 defect was established by this Home assessment.

## What works

- The authored editorial header remains coherent in light and dark themes.
- Populated Home gives people/content quiet weight, Compare focal weight and utilities flat presentation.
- Copy around curiosity, conversation and boundaries preserves the user's agency. The warm opening and reassurance reduce first-use pressure.

Cognitive load is low, with one partial focus issue on empty Home: secondary containers compete with the first action. The emotional weak points occur when privacy/help is difficult to find or a transfer fails without a clear recovery step.

For a first-time user (Jordan), utility recognition is the main concern. For a distracted phone user (Casey), target sizes are sound but secondary actions carry excess visual weight. For an enlarged-text user (Sam), the Home header still needs direct 320px/200% verification; the fixed header height, side tracks and nonwrapping wordmark are a source-level risk, not a reproduced failure.

## Minor observations

- Add `aria-haspopup="menu"` to the header menu trigger to match the menu semantics.
- Remove the doubled separator between utilities and profile actions.
- A visible comparison verb would clarify first use; the accessible label already explains the action.
- The apparent gap below the empty-state header comes from viewport-centered main content, not oversized header padding. Do not reduce masthead spacing to treat that separate composition choice.
