# KinkSync motion direction and implementation plan

**Decision edition · 21 November 2026 · Jordybeer/kink**

Approve one visual direction and a comparative experiment. The proposed first investment is two to three engineering days on a real Home → Profile handoff. Reserve a second engine decision until the same interaction has been seen and interrupted on a phone. The estimates below assume one engineer, access to a high-refresh iPhone, and review by the product owner.

## 1. What the product already tells us

The most promising image in KinkSync is already on Home. A person's name occupies one modest line among other people. Open that person and the same name becomes the title of a private document. **Make the viewer see that change of scale and importance.** A more elaborate page entrance would miss it.

## 2. Three creative directions

| Direction | What the viewer would see and feel | Physical behavior and implementation | Trade-off |
|---|---|---|---|
| **The Open Folio — recommended** | The row's lower rule opens to the width of the reading column. The portrait travels along the margin. The small italic name becomes the destination title. A private status is uncovered by a narrow matte edge that clears the reading line. | Paper has resistance at the start of a pull and comes firmly to rest. Use measured rects and a fixed origin, a small opaque clipped surface and two crisp text sizes. The reading text stays planar. | Demands accurate type baselines, clipping boundaries and a believable handoff when a long alias wraps. Offers a strong identity even on a device with no GPU effects beyond transforms. |
| **Stage aperture** | The chosen row holds still for a beat as a pair of offset apertures opens outward onto the profile. The title is already visible in the slit at mid-travel. For private reveal, a short asymmetric iris opens inside the control. Scene framing can widen as the view moves from list to detail. | Two opaque, complementary shutters move on different axes and land together. Limit the matte to the hero region. A GSAP timeline or WAAPI sequence can drive the edges. A vector iris is an optional local experiment. | Most theatrical and easiest to recognise in a recording. Can obscure context, look like a film intro on repeated navigation, and incur mask paint. Reject if safety text ever sits behind the shutters. |
| **Portrait in focus** | The identity stays optically fixed while the surrounding composition changes depth. A soft-edged pool of light moves from the Home margin to the profile paper. The sharp status glyph resolves within an already steady label lane. | Camera-like push around the selected anchor, one foreground plane and one shallow background plane. Simulate focus with two pre-rendered tonal fields. Use depth only on decoration. | Strongest scene atmosphere and least dependence on straight edges. A weak version looks like a generic zoom. Full-screen blur, motion sickness, contrast loss in light mode and low-end fill rate make this a riskier design. |

**Choose the Folio.** It gives an answer to a specifically KinkSync question, “Whose perspective am I opening?” It also gives revealing an answer a related but distinct physical action. The aperture is the aggressive artistic challenger for the laboratory. Use the focus study as a storyboard/atmosphere reference unless the first two fail. Avoid combining all three treatments on one tap.

## 3. Technology decision

Ranked for this application, including the cost of adding an owner to an existing system. Compatibility indicators below come from the lockfile, published package metadata and official documentation. Peer support is a screening criterion. Browser, build, CSP and device checks are separate gates.

| Rank | Option | Creative control, platform fit, cost and decision |
|---|---|---|
| 1 | Native CSS and Web Animations API (WAAPI) | CSS handles immediate local state and compact masks. WAAPI gives the route decoration explicit keyframes, current time, reverse and cancel with no vendor runtime. Geometry, cleanup, interruption and accessible semantics belong to our small feature controller. First implementation of the Folio. |
| 2 | Existing Motion for React | Keep installed MIT package 12.40.0. React 19 fits its peer range. Presence, layout projection, scoped layout identities, gesture velocity and layout groups fit genuine shared layouts and existing drag/sheet behavior. Good within a mounted subtree. A layout ID alone cannot bridge an offline document load, decide which linked role was selected or author a convincing three-beat transition. Avoid wrapping the router outlet in wait-mode presence. |
| 3 | GSAP timelines + Flip + @gsap/react | Highest authoring control for overlapping beats, labels, scrubbing and reversal. Flip captures geometry across layout changes. Stable outgoing identity and a committed destination are still our responsibility. Core 3.15.1 is already on the old lab branch. @gsap/react 2.1.2 declares React ≥17. Scope useGSAP to the disposable layer, revert on teardown, use contextSafe for later callbacks, explicitly remove external listeners. Compare a lazy lab chunk with the native treatment. Promote only if the approved result or markedly simpler interruption logic justifies the measured delta. |
| 4 | Browser View Transitions / React ViewTransition / Next integration | Browser snapshots can match named elements across compatible updates, and opt-in same-origin document transitions served the old lab. React coordinates captures with commits. The Next guide supports named morphs on links and explicit navigation. Browser history restoration can skip them. Duplicate names, private screenshots, static captured text and temporarily skipped hit targets matter here. Test as an optional transport on the pinned build using synthetic identity only. |
| 5 | Anime.js 4 / React Spring 10 | Anime.js offers modular timelines, scopes, SVG and a WAAPI path. Attractive alternative if choosing one imperative engine from scratch. React Spring's interruptible physics suit direct manipulation and its web package declares React 19 support. Both MIT. Neither supplies a missing production responsibility after the first three choices. Avoid another clock and gesture vocabulary. |
| 6 | Rive | Excellent for a bespoke, authored interactive object. A designer supplies an editable source, exported .riv, artboard and state-machine contract. A client-only React wrapper binds inputs/data and cleans up the canvas. Canvas/WebGL runtime plus WASM, asset decode, memory and renderer lifecycle are material on iOS. DOM retains focus, accessible names and the real reveal action. Self-host every file and verify compilation under the existing CSP. No asset on the critical route. |
| 7 | React Bits / Motion Primitives / Magic UI | Useful references for an individual mask or layout technique. These are component collections with per-example code, dependencies, styling and accessibility assumptions. React Bits identifies MIT + Commons Clause and some third-party effects. **Installed Next matters.** I inspected the distributed 16.4.6 guide and React binaries. The guide describes the React 19.3 APIs. Next bundles an internal React 19.3 canary that exports both, while the project's standalone `react@19.2.4` production module lacks both exports. Bundler aliases can change the effective runtime. The experiment must type-check a tiny named transition and navigate it in the actual production webpack build before adopting it. Avoid a global experimental flag, undocumented internal import, ambient type shim or React upgrade just to animate this route. The current Next guide explicitly distinguishes an app link back from browser Back/Forward/swipe. Preserve history semantics even if a gesture restores instantly.

**GSAP plugin budget.** Use core timelines for the authored beats and add Flip only to its comparison arm. CustomEase earns inclusion only if a reviewed curve cannot be represented by the shared cubic. MorphSVG can animate one decorative seal contour if the two-strip mask demonstrably fails. SplitText fragments copy and complicates wrapping, selection and assistive reading for little gain here. ScrollTrigger serves scroll-linked scenes, which these interactions do not require. Draggable would duplicate the sheet's drag owner and add competition with iOS scrolling. None of these three belongs on the critical route. GSAP uses its own no-charge standard licence, including plugins. Review the applicable exclusions before redistribution.

**Measured package illustration.** I gzipped the published standalone dist files individually. GSAP core was 28,448 bytes, Flip 9,707 and MorphSVG 9,531. The historical Motion DOM script from 12.40.0 was 44,678 bytes. These are reproducible file measurements with different feature sets and exclude React wrappers. The existing application already imports Motion. Use a before/after Next production build, cold transferred bytes and parsed scripts by route to make the shipment decision. Target zero new engine bytes on unrelated routes, and budget at most **40 KiB incremental gzip** for any on-demand winning signature engine pending owner review.

**Rive economics.** The pricing page reviewed offers free .riv export with a splash and lists Cadet from $9/seat/month for unbranded export. Include the artist's authoring and revision time, runtime updates, self-hosted assets and a static fallback in the cost. A small locally drawn mask has no recurring design-asset pipeline. A WASM/CSP conflict is a reason to prefer the DOM solution.

**Tools by value.** (1) GitHub commit history, Vercel deployment identity and device/browser profiling decide what runs. (2) The existing Figma file is a credible composition reference for private reading, setlist and Agenda footer. Use three keyframes of each direction with real type for art review. Figma cannot validate frame pacing or React cancellation. (3) Impeccable's context and bounded critique plus Superpowers-style checkable work units organize review. A fresh Superdesign canvas would duplicate existing visual authority at this stage. (4) GreenSock publishes official agent skills on timelines, React and performance. Motion's AI Kit supplies free docs search, with performance tooling and premium examples under Motion+. Vercel's official view-transition skill accompanies the Next guide. ## 4. Motion grammar and ownership

The repeated gesture is **an edge opens and something already present gains room**. The focal element may travel a substantial distance. Everything the user is reading or aiming at has a stable place. The exceptional moments are opening a person, opening one private answer and changing scene context. Routine navigation and task completion use the existing quieter contract.

| Proposed timing | Use | Shape and depth |
|---|---|---|
| Immediate | Focus, accessible state, input text, hide, lock, errors and safety meaning | Update on the event/React commit. No visual completion callback controls the result. |
| 90–140 ms | Press/release and local confirmation | Keep the existing 140 ms press ceiling. At most one moving internal mark. Keep target geometry fixed. |
| 190 / 220 ms | Selection / bounded disclosure | Preserve existing values and cubic-bezier(.16,1,.3,1). One visible indicator travels from its actual position. On a wrapped filter grid settle locally if a diagonal trip would cross another label. |
| 280 / 220 ms | Existing sheet arrival / exit | Retain existing sheet presets. Drag can carry velocity where the current sheet allows it. Keep existing spring-modal 260/28 and tooltip 300/30 stiffness/damping for their owners. No new bounce on text. |
| 340–420 ms | Deliberate private reveal or explicit reverse navigation | One shallow tension/release. Try cubic-bezier(.32,0,.18,1) for the travelling edge and the existing arrival curve for its short settle. |
| 480–560 ms | Complete Home → Profile phrase | The first response starts at input. Geometry changes early, arrival overlaps travel. Use a shared travel curve (.45,0,.18,1) and a short deceleration. Never impose a 560 ms navigation delay. |
| 480–650 ms | Scene atmosphere on an explicit context change | Precompose tonal endpoints and crossfade once. Status text, chosen item, toolbar and focus update immediately. Existing ambient drift retains its own slow policy. |

**Depth and stagger.** Keep text, focus rings and controls on a flat plane. The optional close edge can carry a short, baked-in narrow shadow. For the aperture challenger alone, explore ≤2° on a decorative edge with perspective around 900 px. Cut tilt at narrow widths, during keyboard resize and under reduced motion. Allow offsets of 30–60 ms among at most three *parts of one action*. Long lists render at once. Travel is determined by measured source/destination rectangles, not by a fixed screen-width slide.

**Architecture and proposed change map.** Names marked “new” are proposed files. Do not build a platform-wide orchestrator before the first feature earns it.

| Owner | Proposed responsibility |
|---|---|
| Existing `lib/motion.ts` + `app/globals.css` | Keep exports that callers use. Keep current CSS token names. Add the two signature timings/curves once to the smallest feature that uses them. Promote to common tokens only on second use. For values shared by JS/CSS, make one canonical value plus a small parity assertion or generate its counterpart at build time if existing tooling makes that cheaper. |
| Existing `components/MotionPolicy.tsx`, `useReducedMotionPreference`, `useMotionActivity` | One live preference, SSR initially still. Respond immediately if it changes mid-flight. Reuse visibility pause for ambient effects. Avoid a second preference store or RAF loop. |
| New lab-local `app/hot/_motion/IdentityHandoff.tsx` | One bounded client provider for the Home/Profile pair. Proposed interface: capture an eligible intent, register one committed target, cancel. Keep mutable animation handles in refs. Feature timeline owns only the decorative identity/edge elements until handoff. Move into a feature component inside the existing access gates only if approved. |
| Existing `ProfileList`/internal `ProfileRow`, `ProfileHero`, route layout | Expose narrowly typed refs or callback registration of avatar/name/role and bounds. Use profile ID + perspective + part in memory. Duplicate names and matching photos are valid. Scope one active participant per part. Never use display text as an ID. Separate target visual span and interactive/focusable parent. |
| Existing `PrivateResponseStatus`, `ProfileTopicRow` | Stable button and allowlisted render branch own disclosure. A pseudo-element owns only the matte's transform. Native CSS or one cancelable WAAPI sequence on that element. Apply the same safe conceal contract to any touched non-plain variant. |
| Existing `ProfileScreen`, `DisclosureBody`, `Accordion`, `Sheet`, Settings and Agenda consumers | React remains the owner of values, render branches, keyboard state, focus and persistence. CSS owns bounded disclosure; Motion owns existing sheet transforms, presence and gestures. No new sheet implementation or row-level animation engine. |
| Existing `AmbientGlow`, `lib/ambientGlow.ts`, role CSS and scene components | One context change chooses endpoint roles. Ambient wrapper owns route offset/opacity. Existing inner orbs own drift transforms. The scene toolbar and local selection read the same semantic state and use existing tokens. |

**Route transaction.** Capture only an ordinary same-tab activation inside the allowed boundary. Measure the visible source once before routing. Let the original link navigate immediately. Register the destination in a layout effect after real data, identity and layout are ready. The host lives within the lock/onboarding/import gates so unmounting the gate destroys the decoration. Use an in-memory generation token and a single active transaction, never a persisted overlay or global route queue. Capture a rectangle and narrowly allowed identity presentation, never `cloneNode` of a row, hero or page. Clamp the start to the visible viewport and abort if the source is offscreen or occluded. Render the real destination with controls active; only a presentational span may be visually substituted. The overlay is inert, aria-hidden and pointer-transparent. No duplicated IDs or focus targets.

**A second input wins.** If a reverse intent has a still-valid origin and destination, take the current interpolated rect or progress and head back from there. For a new profile ID, invalidate old callbacks before starting from the currently visible state. On layout change, remeasure once at a quiet boundary if continuity is obvious; otherwise finish at the committed layout. Clear animations, transient inline styles, observers, timers, ghost data and any hidden-paint flags on completion, error, teardown or supersession. Guard asynchronous completion by generation. The cleanup from an earlier transaction must never unhide/hide the new transaction's participant. React Strict Mode mount–cleanup–mount is a rehearsal condition.

**Which fallback wins.** Cold deep link, missing target, offline cached document, unsupported animation API, loading/error replacement, integrity warning, lock, native edge-back gesture or restored page gets immediate normal navigation. On slow hydration allow only a short neutral source response. If the destination is still unavailable after a proposed 120 ms capture window, discard the pending handoff and leave the loading shell in control. A missing portrait can use the normal initial. A missing source uses no flight. Do not intercept popstate, scroll restoration, modifiers, middle-click, hash links, downloads or native gestures. For an explicit app return use existing navigation semantics and a reverse only if the actual source row can be restored. Never add a second history entry solely to obtain an animation. On pagehide/visibility loss or preference change, remove live decoration and reset sensitive transient material before resume.

**Concurrency and errors.** Open sheets and tours own focus and stacking. Opening one interrupts a route decoration when it could overlap the active surface. An ordinary local control and an ambient transition may run together on separate nodes. Use at most one geometry owner per visual property per element, including inherited CSS transitions. If applying layout and press to one subject, use separate outer/inner elements or suppress the press effect during handoff. A theme change applies new semantic text, controls and background first, then cancels or rebases the decoration against the new tokens. Optimistic edits key feedback to the actual mutation/version: a failed or superseded save cancels success decoration, preserves the recoverable draft and focus, and presents the real error. Motion never retries data writes or invents a saved state.

## 5. Choreography to build and review

### A. Home → Profile and return

| Time from an eligible warm tap | Picture | Implementation cue |
|---|---|---|
| 0–75 ms | The chosen row's lower edge gains definition at the touched end. The eye stays on the name. Neighboring entries keep their positions. | Use the existing row press treatment and one short divider accent, including a consistent keyboard origin. Begin route work now. |
| 55–310 ms | A single continuous rule moves from the row to the profile reading margin and opens across it. The portrait follows the measured path to its hero size. The name's leading baseline travels with it. This is the large visible movement. | FLIP-style endpoint geometry. Interpolate the portrait using a fixed crop and transform its outer box. Render end-size text as crisp text, using aligned source/destination faces and a brief overlap near matching apparent size. Avoid stretching glyphs and avoid a blurry scale-up of a full text snapshot. |
| 180–400 ms | The Home masthead yields its editorial space. The profile utility header takes its final position. The surrounding paper assumes the profile's existing glow as the divider reaches the new column. | Keep safe-area chrome and hit targets anchored. Change only decorative ink/edge beneath the header. Both sets of actions must follow the route's semantic state. No fullscreen dimmer, moving bottom navigation or captured page. |
| 350–520 ms | The name is now the real title. The rule finishes at the document gutter and the portrait is already still; the slight delay makes the landing visible. The document underneath can be read throughout its arrival. | Handoff at matching geometry, then remove the overlay. Render limits, headings and tools as soon as the route commits. No cards enter afterwards. |
| Return | The same edge contracts to the actual prior row; the name reduces in importance as the list takes over. | Proposed 340–400 ms for explicit app return, shorten for partial progress. Preserve original scroll, expanded group and focus destination where supported. If the row is absent after restoration, end cleanly without trying to scroll it into a flight. |

For two linked perspectives, the selected role travels to the hero's role line. The shared group name stays still unless the exact same identity presentation is present and unambiguous. No portrait flight from the other perspective. For a long name, changing line count disqualifies the text morph: carry the portrait/rule and resolve the name at its final wrap. For an avatar viewer button, substitute only its visual child. A tour, lock prompt or error preempts the handoff. A product owner should be able to freeze the middle frame and identify the originating perspective.

### B. Private reveal — uncover one line

The closed row has its usual neutral **Privé** label and eye control. Press it and the little opaque edge adjoining the label draws taut for about 45 ms. From 45–225 ms the edge retracts across the fixed answer lane, leaving the glyph and the first letters visible. A second, narrower seam trails it by 35 ms and catches up. From about 225–350 ms the last letters settle into crisp type and the seam disappears. No sparkle, clasp animation, sound, page dimming or reveal of adjacent answers. Keep the status styling true to its meaning, including a hard limit.

Start with `cf2f81c`'s stable focusable button and reserved lane. Test a transform-only opaque strip over the already-authorized label. Compare with a small inset clip or an isolated, brief blur-to-focus on the entering label if the seam lacks softness. Set width from layout constraints, independent of the concealed value. Only reveal after the eligible local profile and explicit current topic selection permit it. Keep status, glyph, comments, details, data attributes and accessible names neutral/absent while concealed, and preserve sharing/export rules. This app uses local trust and data projection; a presentation effect cannot grant access or make a decrypted local store a security boundary.

**Hide is asymmetric on purpose.** Remove the revealed DOM and accessible value on the hide commit. Only neutral matte can animate afterwards. Close the editor and drop the reveal key on conceal, profile switch or section close as the existing flow requires. Never hold a secret in a leaving presence child, screenshot, canvas, hidden measuring node, clipboard, log, performance mark or route overlay. Keyboard activation keeps focus on the same button. A live motion-preference change cancels the matte. When reduce motion is set, the same button changes its label and glyph immediately.

### C. Search, five filters, selection and inline editing

| Action | Proposed treatment | Product invariant |
|---|---|---|
| Open catalogue | Use one labelled owner action near *Interesses & grenzen*. Its magnifier and leading rule become the leading edge of the full catalogue search field over 190–220 ms. Let the heading and input occupy their true layout at once. On compact screens the launcher can sit below the heading. | It searches the full catalogue. Focus the catalogue heading on open, let input focus deliberately open the keyboard, and restore launcher/scroll/status on close. No new modal or extra management entry. |
| Type, clear, filter by category | Input and results update normally. Allow only the clear mark or category marker a small local change. On zero results show the active constraints and the real reset action. | Preserve aliases, custom subjects, category combinations and the existing reset behavior. Native caret, IME composition and keyboard stay responsive. No per-letter animation, list entrance or input remount. |
| Switch status | Keep five flat choices with fixed glyph/check space, a label and a tabular public count. One short rule ties previous selection to new when adjacent. ### D. Scenes, settings and Agenda

**Scenes.** Start at the setlist, with one selected item and existing intensity arc. Changing the chosen item should register first on its row. Over roughly 110–300 ms, the selector and short contextual rule assume their destination role. The background behind the scene heading and its contextual surface gradually exchange two precomposed matte fields over 480–650 ms. Use the same normalized progress for those decorative surfaces. One field can lighten slightly in the warm theme while its dark counterpart gains depth. Keep normal paper behind text. The colour of an actual answer, intensity, consent warning or aftercare rating takes effect immediately with its label. Do not infer a person's mood or consent from the palette. On repeated selection, retarget the current blend, cap simultaneous layers at two and settle to one. Do not reopen a scene, autoplay a sequence or animate the whole page on load.

## 7. Performance, accessibility and the visual decision

**Frame budget.** A 60 Hz refresh is 16.67 ms, a 120 Hz refresh 8.33 ms, shared with browser work. First measure idle effective refresh with low-power mode, browser version and display settings recorded. Safari and the OS can select a lower rate. A desktop 120 Hz option, emulated phone, RAF counter and screen recording each answer different questions. Report high-refresh results only for hardware actually presenting at that rate.

**How to measure.** Compare the same production webpack build configuration, synthetic fixture, viewport, theme and device. Record one cold navigation per treatment for loading and input latency. Then record five warm forward/return cycles per finalist in a single session. Collect frame interval percentiles, missed presentation slots, longest stall, event-to-next-paint, style/layout/paint, layer count, and JS transfer/parse delta. Use Chrome Performance's frame/paint/layers tracks and Safari Web Inspector Timelines on device. Collect RAF samples separately as a diagnostic; compositor animation can continue when JS is busy. Capture the 1× review recording separately from the timing trace. Note tracing overhead and approximate values instead of claiming precision the device does not expose.

| Acceptance gate | Release target / rejection condition |
|---|---|
| Identity and craft | Across 3 fresh viewers of the two synthetic perspectives, all can identify the selected perspective at the middle beat and what became the title afterwards. At least 2 choose the signature over the baseline at normal speed and can describe the specific visual event without prompting. Aesthetic approval by the owner still decides. **Spend GPU work where the eye will see it.** Geometry transforms and opacity are the default, but a transformed full-screen translucent layer still consumes memory and fill rate. A 390 × 844 viewport at DPR 3 is about 11.3 MiB for a single four-byte-per-pixel surface before tiling, double buffering or extra copies. A local clip or a few frames of small-label blur can be worth a paint. A moving fullscreen backdrop blur, animated gradient-stop field and persistent `will-change` on every row cannot earn that cost here. Sample colours on the rendered tinted backdrop. Avoid per-frame style reads, resampling on every keystroke and promoting long lists.

**Degradation ladder.** First cut the second seam, shadow, tilt and atmosphere overlay. Next retain the single portrait/divider transform and fixed text. Finally render the immediate semantic state. Use reduced-motion preference directly. Choose a tested simpler default on consistently slow paths, and degrade a currently interrupted transition when its prerequisites disappear. Avoid device-model sniffing or a perpetual frame monitor. If a device runs at 60 Hz, evaluate its 60 Hz path; if the 120 Hz path misses budget, record that result and use the cheaper treatment there.

**Bound validation.** One batched design/device review, one correction pass and one confirmation on changed cases. Reuse `e2e/profile-catalog-focus.spec.ts`, `profile-read-summary.spec.ts`, `private-responses.spec.ts`, `profile-share-privacy.spec.ts`, `motion-language.spec.ts`, `motion-accessibility.spec.ts`, `intimacy.spec.ts` and the existing offline/device rehearsal as applicable. Add a small new handoff regression only for the multi-intent cleanup/gated-remount case existing specs miss. Use required CI once per release candidate. If criteria still fail, choose the simpler treatment or return the specific unresolved decision.
